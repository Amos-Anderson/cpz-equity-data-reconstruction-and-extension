  PROJECT OVERVIEW (HIGH-LEVEL)
================================================================================

  The goal is a complete long/short equity factor-investing pipeline for US
  equities, end-to-end, with academic rigor at every stage. Eleven stages,
  from data reconstruction (Stage 0) to live monitoring (Stage 11). The
  project must deliver three things simultaneously:

    (a) Working Python implementation (modular, tested)
    (b) Academic LaTeX report (mathematical, cited)
    (c) Paper-trading deployment on Alpaca

  The ROADMAP.txt v2 contains the full technical plan. Do not rewrite the
  ROADMAP. It is the blueprint. Your job is to execute it.

  CRITICAL DESIGN DECISION (v2 vs v1)
  -----------------------------------
  v1 of the project committed to single methods at each stage. This led to
  problems at Stage 4 — the chosen Ridge regression produced unsatisfying
  results (IC ≈ 0 but spread Sharpe = 1.0) and we couldn't rigorously
  defend the choice.

  v2 commits to EMPIRICAL COMPARISON OVER A PRIORI COMMITMENT. Where
  multiple defensible methods exist, we implement multiple methods and let
  the leaderboard pick the winner. This applies most prominently in Stage 4
  (4 approaches compared) but is a general principle throughout the project.

================================================================================
  PROJECT-SPECIFIC PHILOSOPHICAL PRINCIPLES (FROM ROADMAP V2)
================================================================================

  PRINCIPLE 1: MATHEMATICAL RIGOR FIRST
  -------------------------------------
  Before writing ANY code for any stage, build the full mathematical
  framework and have Amos approve it. Code is a translation of math; if
  the math is unclear, the code cannot be trusted.

  The math framework must include:
    (a) Intuition (why we're doing this in plain language)
    (b) Mathematical formalization (the precise statement)
    (c) Derivation (where the formulas come from)
    (d) Alternatives (what other approaches exist)
    (e) Criticism (what could go wrong, what assumptions are risky)
    (f) References (papers, textbook sections)

  PRINCIPLE 2: DEEPLY PEDAGOGICAL
  -------------------------------
  Treat each stage as if writing a reference textbook. Math derivations
  should be teachable end-to-end. The level of depth in our existing
  Stage 2 neutralization, Stage 3 validation, and Stage 4 framework is
  the BAR, not the ceiling.

  PRINCIPLE 3: EMPIRICAL COMPARISON OVER A PRIORI COMMITMENT
  ----------------------------------------------------------
  Where multiple defensible methods exist, implement them all and compare
  on consistent metrics. Don't choose based on intuition or aesthetics.
  Don't let the literature you know best dominate.

  PRINCIPLE 4: NO POST-HOC FILTERING
  ----------------------------------
  Decision rules (significance thresholds, robustness criteria, weight
  schemes) are LOCKED IN before computation. Whatever number of factors
  pass our criterion is the number; we do not adjust thresholds to hit
  a target count.

  This was a problem in v1 -- Stage 3 used "robust set" cutoffs that
  retroactively shifted to include exactly the factors we wanted. v2
  produces diagnostic statistics for ALL factors and lets Stage 4
  approaches use them however they wish.

  PRINCIPLE 5: HONEST RESULTS REPORTING
  -------------------------------------
  Whatever results emerge from the pipeline are reported as-is, with
  explanations rather than apologies. Surprising findings are valuable
  if methodologically sound.

  PRINCIPLE 6: SINGLE ITERATION PER DESIGN DECISION
  -------------------------------------------------
  Once a design decision is made (e.g., Stage 4 uses Ridge with grid X),
  it is locked. Do not re-litigate it within the same stage. If a better
  approach is identified later, document it as future work, do not
  reopen the decision mid-build.

  The 4 approaches (per ROADMAP.txt v2 Stage 4 entry):
    Approach 1: Statistical filtering + composite weighting
    Approach 2: SVD/PCA orthogonalization

    Approach 4: Risk Premium PCA (Lettau-Pelger 2018)

  Approach 4 requires the Lettau-Pelger paper. Amos will provide it
  when Stage 4 implementation begins. DO NOT IMPLEMENT WITHOUT THE PAPER.

  Lessons from v1 Ridge attempt (do not repeat):
    - CV picked smallest lambda in grid every year -- grid was too narrow
    - CV mean IC ~ 0.04 but OOS IC ~ 0 -- the model overfit CV folds
    - Walk-forward expanding window with no embargo may have allowed leak
    - Spread Sharpe was high (1.0) but IC was zero -- non-monotonic signal

  v2 expectations for Stage 4:
    - Wider lambda grid (e.g., 1e-6 to 1e3)
    - Consider purged + embargoed CV (Lopez de Prado 2018)
    - Each approach gets equal computational budget
    - Leaderboard primary metric: decile-spread Sharpe
    - Tiebreaker: IC Sharpe
    - All 4 approaches saved for sensitivity analysis
    - Single winner feeds Stage 5
